# RFCs

Requests for Comments are how changes to the **standard** are decided: anything that changes `spec/`, the required course structure in [course-format.md](../spec/course-format.md), or the free/paid line in the [README](../README.md#free-and-paid).

Routine fixes — a wrong chapter reference, a broken link, a clearer paragraph — do not need an RFC. Open a pull request directly (see [CONTRIBUTING](../governance/CONTRIBUTING.md)).

## When you need one

- Adding, removing, or renaming a required course section.
- Changing what counts as evidence or a status label.
- Changing the licenses, the DCO policy, or the governance rules.
- Adding a new top-level directory or a new track.
- Anything that would make an existing course or implementation stop conforming (once [conformance](../spec/conformance.md) exists).

## Process

1. Open an issue with the **RFC** issue template.
2. Copy [TEMPLATE.md](TEMPLATE.md) into the issue body and fill it in.
3. Discussion happens in the issue. The steward accepts, rejects, or returns it with reasons.
4. Accepted RFCs become pull requests that link the RFC issue. The RFC is updated with the final decision.

An RFC is decided by the steward, as recorded in [GOVERNANCE](../governance/GOVERNANCE.md). The reasons for a decision are written down in the RFC itself, whether the answer is yes or no.
