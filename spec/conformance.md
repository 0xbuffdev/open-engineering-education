# Conformance

**Status: not yet defined. Nothing conforms to OEE yet, and the phrase "conforms to OEE" is not in use.**

This file will define what an implementation, course, or curriculum must satisfy to claim conformance to Open Engineering Education — for example: which sections a conforming course must have, which evidence rules it must enforce, and how a conforming implementation reports its status labels.

It is deliberately written last. A conformance definition drafted before anyone has implemented the standard would describe imagined practice rather than real use. Earlier conformance work — other teachers, schools, or communities running courses from this format — is what it should be written against.

Until then, the normative documents are:

- [principles.md](principles.md) — the four binding principles;
- [course-format.md](course-format.md) — required course structure;
- [evidence-rules.md](evidence-rules.md) — what counts as an exit check and a demonstrable artifact;
- [status-labels.md](status-labels.md) — `draft` / `tested` / `verified` and what each requires.

Names and marks, including any future "conforms to OEE" mark, are reserved in [TRADEMARKS.md](../TRADEMARKS.md).
