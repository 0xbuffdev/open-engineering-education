# Principles

Four principles define Open Engineering Education® (OEE®). They bind the spec, the reference curriculum, and anything added later. Each one is written to cost something: the "what this rules out" line is the part that matters.

## 1. Evidence over completion

A course is done when its exit check is demonstrable and the artifact runs from a clean checkout. Reading is not completion.

**What this rules out:** checked boxes, watch-time, and certificates that do not link to a reproducible artifact.

## 2. Mechanism before tooling

Learners must be able to explain what happens underneath (source to syscall to CPU to memory; metric to data to model; asset to boundary to control) before they lean on a framework.

**What this rules out:** courses that start and end at a framework's public API, and any exit check that can be passed by rote API use.

## 3. Honest claims

Every course, benchmark, and result states its limits and what it does not prove. Status labels (`draft` / `tested` / `verified`) are shown publicly.

**What this rules out:** implied readiness, cherry-picked results, and describing a course as proven when only one learner has run it.

## 4. Open by default, paid where it costs to run

The curriculum is free forever. Paid products exist for things that cost money to operate (grading, execution, agents, certification, cohorts), and the line between the two is stated in writing and never moved silently.

**What this rules out:** moving free material behind a paywall, and describing the free/paid boundary in marketing language instead of a list.
