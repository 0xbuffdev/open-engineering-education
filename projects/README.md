# Projects and Capstones

Use one top-level folder per project: `projects/P1-reliable-cli-data-tool/`, for example. The capstone definitions and prerequisites are in [plan.md](../plan.md#capstones).

Every project needs:

- `README.md` with setup, commands, tests, demo, limitations, and license;
- `docs/design.md` describing requirements, architecture, decisions, and trade-offs;
- `docs/evaluation.md` with benchmarks or model evaluation;
- a threat model for networked, AI, or security-sensitive projects; and
- a retrospective that names one significant failure and how it was resolved.

Before the security capstone, include a written scope and authorization statement. Only assess the private project environment.
